# Подготовка Lua-раздела Mini App

Изменения подготовлены для текущей версии репозитория `creepyside11/proverka-rakcrmp`. В Mini App: VPS → «Управление установленной программой» → проверить IP, ввести SSH-логин и пароль, сверить отпечаток → «Lua: скрипты и настройки». После подключения можно загрузить текстовый `.lua` (до 256 КиБ), посмотреть список файлов, сохранить настройки скрипта, временно отключить их и заполнить настройки ИИ-автокапчи. Файл с уже существующим именем не перезаписывается. Само сохранение **не запускает** скрипт.

SSH-подключение закрепляется за Telegram-пользователем, закрывается после 10 минут бездействия либо кнопкой «Закрыть подключение». Пароль не записывается на диск. API Token сохраняется только в `/opt/rakcrmp-black/.env` с правами 0600, в ответе панели не возвращается. Настройки скриптов находятся в `/opt/rakcrmp-black/.lua-settings/`, скрипты — в `/opt/rakcrmp-black/scripts/lua/`. При обновлениях следует сохранять эти данные, не делать `git clean`, `reset --hard` или принудительную замену. Обновлятор останавливается при конфликте остальных файлов. Замену `accounts.json` он выполняет только после отдельного подтверждения и создания закрытой резервной копии. Значения `CAPTCHA_*`, заданные непосредственно в окружении службы, имеют приоритет над `.env`.

Настройки — JSON-объект с произвольными названиями, строками, числами, булевыми значениями, списками и объектами, до 16 КиБ и 6 уровней вложенности. Скрипт должен самостоятельно использовать `br.setting` / `br.settings`, старый скрипт автоматически понимать их не начнёт. Общая галочка выключает передачу значений, но не сам скрипт. Не передавайте секреты через Lua-настройки; для ИИ предусмотрено отдельное поле.

## Обязательно про установленную версию

Установщик VPS загружает текущую ветку `main` репозитория `black`, устанавливает Lua 5.4 и проверяет наличие Lua-загрузчика. При обновлении уже установленной программы версия также берётся из `main`; если Lua отсутствует, обновлятор попробует установить его. Работу сценария и доступность ИИ-провайдера необходимо проверить отдельно.

Проверки: `python -m unittest discover -s tests -p 'test_vps_*.py' -q` и `python -m unittest discover -s tests -p test_miniapp.py -q`. Тесты используют локальную SSH-службу и подставные данные; настоящий VPS и Telegram-панель не проверялись.
